# Contributing to NodeCore

## 1. Основные принципы

- Все изменения в проекте вносятся через Pull Request (PR).
- Прямые изменения защищённых веток запрещены.
- Каждый Pull Request должен быть проверен и одобрен другим участником проекта.
- Перед слиянием должны успешно проходить обязательные проверки CI.
- Изменения должны соответствовать архитектуре проекта и текущему Roadmap.
- Автор Pull Request отвечает за устранение замечаний, выявленных при проверке.

## 2. Ветки

- `main` — стабильная версия проекта.
- `dev` — основная ветка разработки.
- `feature/<name>` — разработка новых возможностей.
- `fix/<name>` — исправление ошибок.
- `chore/<name>` — технические задачи и обслуживание проекта.
- `docs/<name>` — изменения документации.

Новые рабочие ветки создаются от актуальной `dev`. Рабочие ветки вливаются в `dev` через Pull Request.

Изменения из `dev` в `main` переносятся отдельным Pull Request после проверки готовности версии к выпуску.

## 3. Code Review

Перед одобрением Pull Request участник должен:

1. Ознакомиться с изменениями и понять их назначение.
2. Проверить корректность реализации и соответствие архитектуре проекта.
3. Обратить внимание на обработку ошибок, безопасность и возможные побочные эффекты.
4. Проверить результаты обязательных автоматических проверок.
5. Оставить одобрение либо запросить исправления.

Автор Pull Request не одобряет собственные изменения. Одобрение должен предоставить другой участник проекта.

Автор отвечает за устранение замечаний. После существенных исправлений ревьюер должен повторно ознакомиться с изменениями.

## 4. Слияние изменений

Pull Request можно слить только после выполнения обязательных условий:

- получено одобрение другого участника;
- обязательные проверки CI завершились успешно;
- все блокирующие замечания устранены.

Защита веток GitHub должна обеспечивать выполнение этих условий технически. Участники не должны обходить установленные ограничения.

## 5. Качество кода

Перед отправкой Pull Request необходимо проверить тесты, статический анализ и форматирование кода.

Команды проверки:

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Если проверка выявляет проблему, её необходимо исправить до слияния изменений.
